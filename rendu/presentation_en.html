Real image or generated image?

Detecting AI-generated images with a CNN and transfer learning
ResNet50 · TensorFlow / Keras · Kaggle GPU
Team: Thierno DIALLO (team head), Joe VASEEKARAN, Lisandru ZUCCARELLI, Noé PAYAN
Submitted on 9 December 2026
Introduce the team and the topic in one sentence: we want a model that tells whether an image is a real photo or an image entirely generated by AI.
The problem

Classify an image, even from a generator never seen

  • Task: binary classification, real (camera photo) versus generated (GAN, diffusion, Midjourney…).
  • The real difficulty: new generators appear every month. A useful detector must recognise a generator absent from training.
  • Course constraints: CNN + transfer learning, TensorFlow / Keras, free GPUs (Kaggle T4).

Question 1

What score do we get when every generator is known?

Question 2

Does the model generalise to generators it has never seen?

Approach

Decide everything before coding, then iterate: training run 1 → analysis → training run 2.

Stress question 2: it is what makes the topic interesting. A detector that only works on the generators it knows is useless in practice.
Key decisions · pitfalls avoided

The danger: a model that learns a shortcut

Pitfall 1 · file format

In raw GenImage, real photos are JPEG and generated images are PNG. The model learns “JPEG = real”, not AI (Grommelt et al., Fake or JPEG?).

→

Debiased dataset

unbiased-tiny-genimage: everything is JPEG quality 96. 5,828 real images, 7 generators × 2,500.

Pitfall 2 · image size

BigGAN 128 px, ADM 256 px, SD 512 px, Midjourney 1024 px. Resizing each image differently leaves interpolation traces specific to each source.

→

Same transformation for all

128 px crop at native resolution, then the same ×1.75 upscaling → 224 px.

Pitfall 3 · a misleading score

95% accuracy does not prove the model looks at the right signal. Imbalanced classes = misleading accuracy.

→

Anti-shortcut checks

50/50 classes, AUC + score per generator, perturbation test, Grad-CAM.

This is the methodological core. The literature shows that on raw GenImage a model can reach a high score just by detecting the file format. We chose the dataset and the preprocessing to close these doors. Pitfall 3 sets up the perturbation test, which will reveal another shortcut.

Metrics: accuracy, F1, AUC, confusion matrix, detection rate per generator. Threshold 0.5.

Why Midjourney and BigGAN?

  • The two extreme sizes: 1024 px and 128 px.
  • Two different families: an older GAN and a recent commercial generator.
  • The model then only trains on diffusion models: a demanding test.
The held-out test holds 5,000 generated images for about 875 real ones: its accuracy is misleading, so we look at AUC and per-generator rates.
Configuration · the network

Pre-trained ResNet50 + a light head

Phase 1 · feature extraction

Backbone frozen, only the head learns (2,049 parameters). Adam, lr 1e-3.

Phase 2 · fine-tuning

conv5 unfrozen (~15 M parameters), lr 1e-5 (100× lower). BatchNorm kept frozen.

Why ResNet50?

Reference backbone in detection (Wang et al. 2020), fits the GPU budget. The protocol matters more than the backbone.

Two phases: first the head learns without damaging the ImageNet weights with large gradients, then we adapt the last, most specialised block. BatchNorm stays in inference mode, otherwise its statistics would be recomputed on our batches and destroy the pre-training. 23.6 M parameters in total.

Optimising the tf.data pipeline

In run 2, random blur and JPEG saturated the CPU (the GPU was waiting).

  • Cache of decoded images in memory.
  • Degradation applied to a window around the crop, aligned on the JPEG grid.
  • Checked: 168 cases, 0 pixel difference. 23.4 ms → 5.4 ms per image.
No hyperparameter search: the GPU budget allows one run per experiment. The optimisation was checked pixel by pixel: same result, 4× faster.

“All generators” experiment. “Held-out”: 4% → 38% and 40%.

The model learned “sharp = real”

A photo recompressed by WhatsApp or Instagram would often be flagged as generated. 95% on clean images is not enough.

Good news

The “JPEG = real” shortcut is gone: recompression pushes towards “generated”, not the other way round.

Grad-CAM agrees

Correct answers focus on textured areas. The errors: real photos with smooth areas (white feathers, aerial view).

Fix decided

Blur + JPEG augmentation on both classes (Wang 2020), more epochs, crop grid.

This is the key moment of the talk: a high score is not enough. The model relies on fine details (sensor noise, micro-textures). When a real photo loses them, it looks like what the model associates with AI.

Training augmentation: blur (p 0.5, σ 0–2) and JPEG (p 0.5, quality 50–100), both classes.

Detection of generated images does not drop under perturbation (0.89 to 0.96).

Limit: beyond σ = 2, the “smooth = generated” link comes back. It was pushed back, not removed.

The success criterion set after the first run is met. JPEG 40 is stronger than anything seen in training and is still handled well. Blur σ = 2.5 goes beyond the augmentation range: the model does not generalise past it.

The grid cuts both ways

  • Standard tests: the grid recovers almost all of the loss, false alarms divided by 2 to 3.
  • Unknown Midjourney: 85% → 60%, while the AUC stays at 0.98. The threshold no longer fits, the ranking is fine.
  • The 8 border crops land on smooth backgrounds (bokeh): averaging dilutes the signal.
BigGAN does not change with the grid: its images are 128 px, so the 9 crops are identical. When Midjourney is seen in training, the grid improves it slightly (0.880 → 0.896). A perfect example of an evaluation choice that changes the conclusion.

Selected model: run 2

Slightly weaker on clean images, but it no longer mistakes a recompressed photo for an AI image. This is the one we would use in practice.

Validity of the numbers

~125 images per generator in the test set: 1 image = 0.8 point. A single run per experiment. Real images from ImageNet only.

Gaps of 2 to 3 points on a single generator are statistical noise. Run 1 is still useful: it shows why the augmentation was needed.
Limits and improvements

What is left to do

Limits

  • Strong blur (σ = 2.5): ~50% false alarms.
  • Smooth manufactured surfaces mistaken for AI.
  • A 128 px crop sees 1/64 of a 1024 px image.
  • Real images: ImageNet only, little variety.

Without retraining

  • Aggregate the grid with the maximum (or top-3) instead of the mean.
  • Threshold chosen on validation: an AUC of 0.98 shows a better threshold exists.
  • AUC per unknown generator.

With retraining

  • Blur up to σ = 3, downscale-upscale as augmentation.
  • Other backbones (EfficientNet, ConvNeXt).
  • Test on a more varied set (phone photos, social media).
Robustness comes from the augmentation: it does not extend on its own beyond what the model was shown. The no-retraining ideas are free and target the Midjourney problem directly.
Conclusion

Key takeaways

1 · A detector that generalises

ResNet50 + transfer learning: AUC 0.98–0.99, and never-seen generators detected (94% BigGAN, 85% Midjourney).

2 · Data and protocol matter more than the model

A debiased dataset and an identical native crop closed the format and size shortcuts.

3 · A good score is not enough: test robustness

The perturbation test revealed “sharp = real”. Blur + JPEG augmentation divided false alarms by 3 for ~2 points of clean score.

End on message 3: it is the methodological lesson of the project.
